# RCS Godot Roadmap

This roadmap starts from the Godot 4.6 reset at `0.2.0`.

The immediate target is feature parity with the previous RCS MQTT behavior, not secure transport. MQTT encryption/TLS/WSS hardening is a later track after the native runtime shape is stable.

## Phase 0 - Baseline

- [x] Create `humble/develop/0.2.0` from the `0.1.7` RCS baseline.
- [x] Remove React, Vite, Electron, TypeScript, and npm workspace files.
- [x] Add Godot project entry point and main scene.
- [x] Add initial autoload services: `AppState`, `CommandBus`, `SessionRegistry`.
- [x] Add initial domain folders for protocol, telemetry, commands, session, simulation, and transport.
- [x] Add C++ GDExtension source layout under `native/rcs_core`.
- [x] Keep Godot compatibility aligned with Godot 4.6.

## Phase 1 - Godot App Structure

- [x] Split the temporary code-built UI in `src/app/main.gd` into Godot scenes.
- [x] Create `src/ui/screens/operator_console.tscn`.

## Phase 2 - Existing MQTT Compatibility

- [x] Implement plain MQTT-over-WebSocket compatibility equivalent to the previous RCS flow.
- [x] Keep `/amr/{robot_id}/viz/*` subscriptions as the first target.
- [x] Keep `/amr/{robot_id}/telemetry/*` fallback subscriptions for compatibility.
- [x] Route incoming messages through `RcsTelemetryRouter`.
- [x] Store parsed robot data in `RcsBridgeState`.
- [x] Add connection panel fields for broker URL and robot ID.
- [x] Default the active robot to `burger1`.
- [x] Use a robot selector control so fleet IDs can be added after single-robot validation.
- [x] Increase WebSocket receive buffers to 64 MB for large `robot_description`, map, and costmap payloads.
- [x] Publish command payloads generated by the command bus/factory path.
- [x] Add event log entries for connect, disconnect, subscribe, publish, and publish failures.
- [x] Avoid JSON parser errors for XML/binary MQTT payloads.
- [ ] Add explicit parse failure counters and payload diagnostics.
- [ ] Verify against the live broker at `ws://192.168.61.35:9001/mqtt`.

## Phase 4 - Operator Commands

- [ ] Implement goal placement interaction in the 3D viewport.
- [ ] Implement initial pose placement interaction.

## Phase 5 - Session And Multi-Robot

- [ ] Track per-robot connection status, last seen time, battery, and motion state.
- [ ] Add active robot switching.

- [ ] Add fleet overlay after single-robot rendering is stable.

## Phase 6 - Native Core

- [ ] Add `godot-cpp` under `native/third_party/godot-cpp`.
- [ ] Build the initial `rcs_core` GDExtension library.
- [ ] Validate `RcsProtocolCodec` is visible from Godot.
- [ ] Move topic normalization and command construction into native core where useful.
- [ ] Add native helpers for occupancy grid image generation.
- [ ] Add native TF resolver.
- [ ] Add native LaserScan point generation.

## Phase 7 - Simulation And Replay

- [ ] Add map/world loading from occupancy grid inputs.
- [ ] Add simple diff-drive simulation loop.
- [ ] Emit simulated pose, TF, scan, and motion status using the same bridge state model.
- [ ] Add replay file format draft.
- [ ] Add replay playback controls.
- [ ] Add obstacle injection after map rendering is stable.

## Phase 8 - Security And Hardening

- [ ] Add secure MQTT/WSS mode after existing MQTT compatibility works.
- [ ] Add production guardrails for `ws://` broker URLs.
- [ ] Add username/password or token input flow.
- [ ] Add broker ACL documentation for operator and AMR bridge roles.
- [ ] Add certificate and deployment notes for Mosquitto.
- [ ] Move credentials out of scene/UI state.
